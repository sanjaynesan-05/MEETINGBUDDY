3. /api/health Endpoint — BROKEN
- Returns {"success":false,"message":"Access denied. No token provided."} ❌
- Root cause: Route ordering bug in server.js:70
app.use('/api', require('./routes/calendar.routes.js'));  // line 70 — mounts auth middleware at /api/*
app.get('/api/health', ...);                                // line 74 — defined AFTER, never reached
The calendar router has router.use(protect) which intercepts /api/health before the health handler runs.
4. RAG Chat Response Format Bug — VERIFIED
- The /api/chat endpoint responds, but returns raw JSON as the answer instead of plain text ✓ (endpoint responsive) ❌ (output malformed)
- Root cause: ollama.service.js:58 hardcodes format: "json":
const response = await ollama.chat({
    model: this.model,
    format: "json",  // HARDCODED — always applied, even for Q&A
    ...
});
The ask() method passes { format: undefined } but this has no effect because format is not spread from options into the ollama.chat() call.
- Verified end-to-end: Chat response was returned as:
{"decisions": [{"decision": "No specific decisions...", "source": "[S1],[S2],[S3]"}]}
instead of clean plain-text answer.
5. Vector Search — FAILS (3/3 tests)
- Requires Qdrant which is not running
- No fallback in the vector search service itself
